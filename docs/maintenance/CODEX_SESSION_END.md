# Codex 收尾与同步

2026-10-18：应用内置 Codex 0.163.0-alpha.10.2 的 SessionEnd 最多 3 秒；把 timeout 写成 20/30 秒不会延长实际执行。该事件即使配置 async 仍同步执行，见 [官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)。

## 会话结束只检查

`.codex/hooks.json` 的 SessionEnd 只调用 `scripts/session-end-status.py`，外层 3 秒、Git 查询内部 1.5 秒预算。保留原 SessionStart 行为，不新增 Stop 钩子或常驻服务。

检查不联网、不调用同步脚本、不读取记忆正文或凭据、不写日志或状态文件、不暂存或修改 Git index；禁用 Git 可选锁、外部 fsmonitor 和按需远端取对象。检查只报告工作区是否有改动，以及相对本地 upstream 缓存的领先/落后数，不输出文件名。不检查子模块内部；查询失败或超时明确报告未知。结果输出到钩子执行结果；关闭应用时不保证出现独立通知，不能以是否看到提示判断已经备份。

**关闭 Codex 不再自动备份未完成代码或未显式同步的项目记忆。** 文件仍留在本机；本地保留不是远端备份，设备损坏风险仍在。中途关闭、崩溃或钩子没触发都不能依赖它保存/传送工作。

## 完成并验证后的显式收尾

1. 确认任务已经完成并通过相应验证，再审改动；回答结束本身不是完成信号。确认所在分支与文件归属，保护并行会话/工作树。
2. 用明确文件清单暂存，只提交本任务成果；核对完整暂存 diff，若有他人已暂存内容，不一并提交或替对方重置。不使用 `git add -A` 或 `git-sync.sh push` 自动收尾，也不擅自处理其他会话的分支。
3. 在当次授权范围内显式推送，检查命令结果并核实目标分支的远端提交；失败就报告未推送，不把本地 commit 或缓存当上线/同步证据。本轮钩子修复用户要求不提交推送，照此保留本地补丁。
4. 项目记忆与代码是两条通道：`.claude-memory/` 不进 Git。需要同步时，在当次允许的范围内显式执行现有记忆同步，保持原目录、原对端和增量策略；不得通过提交记忆目录到公开仓库替代它。
5. **现有 `memory-sync.sh` 会隐藏 rsync 错误并返回 0。** 隔离测试复现 rsync 返回 23 时脚本仍返回 0。因此仅运行该脚本不能确认成功；需另行核实同一对端的实际传输结果或文件内容，未核实就写“记忆同步结果未知”。不能编造本地成功记录，也不能把较新时间戳当逐字节一致。本次不执行真实同步或远端核实。

显式提交、推送与记忆同步在正常命令执行阶段进行，可以等待合理的网络超时，不受 SessionEnd 的 3 秒预算限制，不通过脱离管理的后台进程绕开限制。
