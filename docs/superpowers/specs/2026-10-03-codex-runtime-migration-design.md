# searchX 后台迁移到 Codex：现状核实与实施方案

日期：2026-10-03（北京时间）。状态：用户已同意开始隔离测试；执行层在任务分支实施，未改生产程序、未启用服务。

## 1. 目标与已确定的要求

接管原 Claude Code 的完整工作流程：网站接单后自动研究、股票数据核准、质量检查、独立核验、发布、通知，以及私密核查。Stocks 已有报告继续自动导入。

用户本次明确要求：所有新接入的模型调用固定 **`gpt-6.1-sol`**，思考等级最低 **`high`**。默认使用 high；写作、核验、修订、核查均显式传参，不能继承个人配置或子代理默认值。更高档必须同时在安装版模型目录中得到支持。配置成 low/medium、未知档位或其他模型时启动报错；登录、额度或模型失败时不自动换模型、不转 API 计费。

这里区分两个承诺：迁移保证旧流程与质量规则完整执行；不同模型的具体报告质量仍需真实样本审查，不能靠模型名称或单测保证相同。

## 3. 方案选择

| 选项 | 代价与边界 | 结论 |
|---|---|---|
| 保留现有服务，增加受控的 Codex 执行层 | 改动模型调用与执行权限，沿用队列、查重、格式、网站、通知；需要补齐真实接线验收 | **推荐** |
| 重写为 OpenAI API 服务 | 需要另配 API 计费、鉴权和工具编排，迁移范围明显扩大 | 本次不选 |
| 在聊天窗口手工运行研究 | 可以出单篇，但关窗口后的接单、重试和通知仍不成立 | 只能作为临时人工入口 |

推荐继续在 Mac mini 无人值守运行，复用该机已安装 CLI 与 ChatGPT 登录。开发机负责代码与离线测试，不消费生产队列。

## 4. 推荐流程

### 公开研究

网站提交 → 原 Worker / approved Issue → 原 20 天股票查重 → Codex 研究写作 → 机器质检与联网数字回链 → 2–3 个独立只读 Codex 核验任务 → 定点修订（最多两轮）→ 合格产物归档 / Obsidian 转换 → 精准发布 → 原上线确认和邮件。

适配重点：

1. **技能显式加载。** 由程序提供 `.agents/skills/research`，股票分流完整保留 A–M 与 stock 数据规则；不把 `/research` 字符串当成 Codex 已注册的命令。网页、题目、侧重点均作为不可信素材传入。
2. **模型执行与发布分开。** 写作发生在独立临时工作目录，只提供本任务所需技能、模板、报告索引和输入。模型不读取生产 `.env`，不负责 git push、队列写入或发信；这些动作由已有服务和受控发布步骤执行。
3. **独立核验保持独立。** 调度器启动全新上下文的核验任务，只给成品、来源及机器质证清单，不给写作者推理。核验员能联网回查但不能改文件；同样固定 6.1 Sol / 至少 high。三视角覆盖数字日期及现状、来源指向、逻辑与证据强度。
4. **保留全部原有质量口径。** `research-qc --strict` 拦硬红线与检查失败；`check-web-numbers --challenge` 提供质证清单，不把抓取失败改成事实错误。核验硬错须有“报告说 X / 来源说 Z / URL”证据。缺少独立核验结果不能按通过发布。
5. **产物可核对。** 关联任务 ID、目录、模型、思考档位、退出原因、质检与核验结果。不能只因退出码 0 或多了目录就宣布成功；生成、核验、归档、上线、通知分别记录。
6. **搁置与恢复。** 保留主题 `.parked` 和 runner 搁置信号的区别；只回滚本任务索引条目。未过核验的草稿不能被 importer 或自动同步钩子带上公开站。
7. **并发与超时。** 保留心跳和锁绝对时限；总研究预算默认仍为 180 分钟，覆盖写作、核验、修订，不为每个阶段重置预算。超时终止整个任务进程组及其工具进程。
8. **生产工作树交付。** 临时产物回写与 importer、autopull、同步钩子的并发需要明确互斥；最终只暂存本任务报告与对应索引变化。发布失败从已核验产物继续，不能重新花额度研究。

### 私密核查

保留原 KV 队列、图片下载、父任务补证、`result.md` 的 title/summary、结果回传缓存、失败上限、7 天 TTL、手机详情与通知。模型切换到同一受控 Codex 执行层。

图片只提供本任务白名单文件；本机路径和截图正文不能进入公开研究目录。沿用轻量承重事实复核，不把公开研究的 2–3 核验任务强加给私密核查。Obsidian 文件和回传全文由受控步骤写入；无产物不能标完成，回传失败只补回传。

### Stocks 的两条联动

- **已完成报告搬运：** 现有 importer 按 `research_report` 内容读取，不筛 Claude engine，所以 #165 已自然流入。保留按目录取最新版后再按 ID 排重、清洗、价位改写、机器质检、搁置和精准发布；不需要改 Stocks 表结构或重跑存量报告。
- **searchX 新研究取数：** 仍只读市场数据。优先复用 Stocks 已有的 `codex_query_mcp.py --scope research --user-id none` 与查询白名单。实施时逐项核对 searchX stock §2.3 的需求覆盖；缺口通过 searchX 侧固定只读查询补齐，不能因某个聚合工具缺字段而把股票章节删掉。所有连接保留 busy_timeout 在 query_only 之前与锁失败重试，原始返回同步存档以供数字对账。禁止私人范围和任意 SQL。

Stocks 的 `lib/headless_codex.py` 可参考其模型钉住、ChatGPT 鉴权、环境剥离、Code Mode、完成事件识别和进程组回收；不能整份照搬：它关闭图片和子代理，也不生成网站三件套，不满足 searchX 的全部职责。

## 6. 验收与切换顺序

1. **本地离线验收：** 配置不得低于 high、不得换模型；stdin 注入边界；隔离环境无业务/API 密钥；CLI 错误、超时、半份产物、核验缺失、搁置、回传失败均有确定性测试。采用不含 `.env` 的临时源码镜像，禁止运行生产装配入口。
2. **常驻机隔离能力测试：** 核实确实以 6.1 Sol/high 完成回合，真实联网抓原文、Stocks 只读取数、图片识别、受限写作、核验只读与进程回收。只检查 `login status` 不算此步通过。
3. **真实内容验收：** 一篇股票研究、一篇非股票研究、一条图片核查。先输出隔离产物；审查内容、取数覆盖、来源、独立核验、三件套与 Obsidian 转换一致性。样本可以复用已有主题用于对照，但不能让查重直接返回旧报告冒充新模型验收。
4. **Stocks 回归：** 对全部存量导入映射与重复 ID 做只读重放；#165 作为新引擎格式样本。任何构建/转换/查重改动均按项目约定跑全部存量；涉及网页或联动体验时用真浏览器验证正常与失败路径。
5. **生产切换前检查：** 核对待处理队列数量和历史失败缓存，确认旧 Claude runner 仍停止，避免启用后意外批量消耗；同步代码与技能、核对实际 SHA 后只运行批准的测试任务。
6. **最终链路：** 单条网站任务从提交、模型执行、核验、页面可达一直核到通知；私密任务核到手机详情。确认后才恢复周期执行。保留首个自然任务观察；服务 loaded/退出 0 不能代替结果验收。

步骤 1 可在开发机完成；涉及推送部署、启停服务、真实队列、邮件/Bark 与外部笔记写入时，按当前会话授权边界确认。用户已确定模型要求；本次尚未执行上述生产动作。
