## 1. 位置式触发价位（已修复、已上线）

**缺口**：「股价仍处于筹码加权平均成本 84.28 元下方，那么可小幅试仓」这类句子不带「跌破 / 站上」这些触发动词，`TRIGGER_PRICE_RE` 抓不到。2026-08-31 指南针那篇是手工改掉的，规则一直没补。

**标定**：先对 179 篇存量扫「价位 + 上方 / 下方 / 之上 / 之下 / 以上 / 以下」的全部写法。只加「处于」一个词一条都抓不到，真违规写的是「可在 45 元下方分批试仓」「股价重回筹码加权成本 84.28 元上方」「站回 250.80 元之上」「挑战 50 元上方」「下探 220 元以下」「区间参照 50% 分位 54.00 元上方」「→ 45 元下方分批」。动词表照这些原文收。

**规则**（`scripts/research-qc.js` 的 `POSITION_PRICE_RE` + `positionTriggers()`）：判据是价位后紧跟方位词；复用原有的条件句 / 操作结论 / 过去时 / 引用 / 基准价 / 商品价 / EPS 豁免，另加三类只对位置式生效的豁免，都是存量里标定出的误报：
- 主语是筹码刻度本身（「持仓成本在 329.00 元以上」）；
- 主语是产品价格（「光模块价格将维持在 700 美元以上」），但「股价 / 市价 / 行情价格」不算；
- 同一分句的主语是现价 / 收盘价（「当前价 269.33 元（日期）位于成本线 241.20 元之上」）。

存量结果：误报修到 0，真违规 11 篇。每条豁免和守卫都做过变异验证（拆掉就有测试变红）。

**存量整改**：11 篇的 report.html / notes.md 已改成相对表述（1 篇本站自产的三花 06-05，10 篇 Stocks 导入的）。同一段情景路径里 QC 没抓到的同类价位也一并改了，例如括号写法「筹码加权成本（253 元附近）上方」「15% 分位（220.40）」。Obsidian 里的全文笔记是私人的，没动。

**导入侧同步**（`services/stocks-import/src/price-anchor.js` 形态三）：11 篇里 10 篇是 Stocks 导入的，只改质检的话每天导入会有一部分被搁置、发报警。改写器现在也处理位置式：**判定直接调 `positionTriggers`**，不另写词表，所以 QC 放行的现状陈述改写器也不碰；只剥「有锚」的数值，裸价位和区间照旧留给 QC 搁置。Stocks 原文里常见的 `**…910.20 元**下方` 这种加粗写法也认，剥完加粗符号仍然配对。

## 7. 数字核查三处问题（已修复，`d418e19` + `c411a01`）

只动了 `scripts/check-web-numbers.js` 及其测试（39 → 53 条，每条规则都做过变异验证）。

- **假「已找到」**：整数碰上页面上的「N.xx」时，只有四舍五入对得上、且紧跟与报告同一个单位（亿/万/%/吨…）才认；小数部分全是 0 的视同同一个数。换算那一档改成读页面上那个数后面跟着什么：紧跟别的量级单位的不认；表格里的裸数要带千分位或小数点，且全页确有「万元」「千元」这类口径词。千以内的整数（这类数只因为带了亿/万/% 才进核查清单，数值本身没有辨识度）连原样命中也要求紧跟同单位；英文页的 percent、万亿对应的 trillion 也认。
- **港股「百萬」**：亿 ×100，页面上的数必须紧跟「百萬 / 百万」才算；正好相等算强证据，靠四舍五入容差对上的算弱档。
- **报错原因**：是不是 PDF 看文件头 `%PDF-`，不看链接后缀。链接说是 PDF、内容却不是的，如实写「返回的是网页不是 PDF（可能是反爬验证页）」；找不到 pdftotext 和疑为扫描件分开报。

**核对**（22 篇、同一批缓存的真实响应回放，已找到 / 待质证 / 未测；这组数字是子代理算的，我另写回放脚本独立复现过，逐篇一致）：合计 704/310/222 → 680/334/222。「已找到→待质证」共 29 条，其中 27 条是修掉的假命中（撞上行情侧栏股价、别的股票代码、链接里的编码串、「20-year」「10:30」「$200 million」这类别的量）；另外 2 条是真命中被误伤：报告把 42.53% 截成「42%」而不是四舍五入；「70,650 平方毫米」对应页面上的「~70,685 mm²」，英文单位认不出来。智谱那篇的 313.75 亿港元、48.96 亿港元现在能找到了；上交所那两条 PDF 链接如实报成反爬页。

**残留局限（只是说明）**：弱档里仍有几条巧合命中，但都已标成「换算命中」、不算强证据；单位只写在表头的表格里，小整数会进待质证；英文里「$20.0 billion」「$1,350 million」这类写法仍然只按精确串匹配；判别力自检只用两位小数的虚构数，看不出这类错误。
